## 12. Чем отличаются fit, transform и fit_transform?

- `fit` узнает параметры из данных: например, среднее и стандартное отклонение каждого признака.
- `transform` применяет уже найденные параметры.
- `fit_transform` последовательно делает обе операции.

В нашем коде:

```python
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

На train учимся и преобразуем, на test только преобразуем. Аналогично `pca.fit(X_train_scaled)` нашел бы направления компонент, а `pca.transform(X_test_scaled)` спроецировал бы тестовые данные на эти направления. У регрессии `fit(X_train, y_train)` обучает коэффициенты, а для прогноза используется `predict`.

## 13. Как исключено обучение предобработки на test?

Для наглядного анализа:

```python
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

Для моделей:

В `search` находится `Pipeline`, поэтому scaler и PCA обучаются вместе с моделью только на разрешенной обучающей части. `X_test` появляется лишь в `predict`. Внутри кросс-валидации действует то же правило: проверочный фолд не участвует в `fit` преобразований.

## 15. Какой метод корреляции выбран и почему?

Явно указан `method='pearson'` — коэффициент Пирсона. Он оценивает **линейную** связь, которую мы исследуем перед линейной регрессией. Значение около 1 означает сильную положительную связь, около −1 — отрицательную, около 0 — слабую линейную связь.

Корреляция около нуля не исключает нелинейной зависимости. Пирсон чувствителен к крайним значениям, поэтому рядом исследуются распределения и выбросы. Корреляция не доказывает причинность.

## 17. Как считается VIF и как его понимать?

```python
X_vif = add_constant(numeric_df.drop(columns=['PRP']).dropna())
vif_data = pd.DataFrame({
    'Признак': X_vif.columns[1:],
    'VIF': [variance_inflation_factor(X_vif.values, i)
            for i in range(1, X_vif.shape[1])]
})
```

Для каждого признака строится вспомогательная регрессия на остальные: `VIF = 1 / (1 - R²)`. Чем лучше остальные объясняют данный признак, тем больше VIF. Константа нужна, чтобы такая регрессия включала свободный член. Ее VIF не выводим, поэтому перебираем столбцы начиная с 1. Цель `PRP` в этот расчет не входит.

Получено: **MYCT 1,202; MMIN 2,902; MMAX 3,274; CACH 1,858; CHMIN 1,966; CHMAX 1,891**. Значение 1 означает отсутствие линейной связи с остальными признаками. Значения выше 5 обычно требуют внимания, выше 10 — указывают на серьезную проблему; это ориентиры. У нас **сильная мультиколлинеарность по этим порогам не обнаружена**.

## 24. Как подбирается alpha и какие значения проверяются?

```python
alpha_values = [0.01, 0.1, 1.0, 10.0, 100.0]
param_grid = {} if name == 'Linear Regression' else {'model__alpha': alpha_values}
search = GridSearchCV(
    pipeline, param_grid, cv=cv,
    scoring='neg_root_mean_squared_error', refit=True
)
search.fit(X_train, y_train)
```

Перебираем пять значений и выбираем то, у которого минимальный средний RMSE на проверочных фолдах. `model__alpha` означает параметр `alpha` у шага `model` внутри Pipeline. Для линейной регрессии сетка пустая: оценивается один вариант.

И до, и после PCA выбраны **Ridge: alpha=100; Lasso: alpha=10**. У Ridge выбран край сетки, поэтому это лучший параметр **среди проверенных**, а не доказанный глобальный оптимум. Если продолжать исследование, можно расширить сетку, по-прежнему используя только train.

## 25. Где кросс-валидация, сколько фолдов и какая метрика?

```python
cv = KFold(n_splits=5, shuffle=True, random_state=42)
search = GridSearchCV(
    pipeline, param_grid, cv=cv,
    scoring='neg_root_mean_squared_error', refit=True
)
```

Используется **5 фолдов**: модель обучается на четырех частях и проверяется на пятой. Проверочная часть меняется пять раз. Для каждого `alpha` считаются пять ошибок и их среднее.

Scikit-learn выбирает максимальный score, поэтому для ошибки используется отрицательный RMSE. Чтобы вывести привычное положительное значение, в коде стоит `-search.best_score_`. `CV std` показывает разброс ошибок по фолдам. Выбранный по этим же фолдам результат может быть оптимистичным, поэтому отдельный test нужен для итоговой оценки.

## 26. Где выполняются масштабирование и PCA во время CV?

Они находятся **внутри Pipeline**, который передан в `GridSearchCV`:

```python
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('pca', PCA(n_components=0.90, svd_solver='full')),
    ('model', model)
])
search.fit(X_train, y_train)
```

На каждом фолде scaler и PCA обучаются заново только на его обучающей части. Проверочная часть проходит лишь `transform`. Передавать в поиск заранее рассчитанный `X_train_pca` нельзя: тогда информация из проверочных частей уже участвовала бы в настройке PCA.

## 27. Используется ли Pipeline и зачем каждый шаг?

До PCA:

```python
Pipeline([('scaler', StandardScaler()), ('model', model)])
```

После PCA:

```python
Pipeline([
    ('scaler', StandardScaler()),
    ('pca', PCA(n_components=0.90, svd_solver='full')),
    ('model', model)
])
```

`scaler` приводит признаки к сопоставимому масштабу. `pca` строит компоненты и уменьшает число признаков. `model` обучает регрессию. При `predict(X_test)` конвейер сам применяет обученные преобразования в правильном порядке, а затем получает прогноз.

| CHMIN | 2,367 | 13,451 | 0,000 |
| CHMAX | 32,387 | 23,138 | 25,533 |

Коэффициенты относятся к **стандартизованным** признакам. Например, у линейной регрессии увеличение `MMAX` на одно стандартное отклонение при фиксированных остальных признаках меняет прогноз примерно на 64,58 единицы `PRP`.

Ridge сдерживает общую величину коэффициентов, но отдельный коэффициент может увеличиться. Lasso обнулил `MYCT` и `CHMIN`. Знак коэффициента при совместном учете признаков может отличаться от знака парной корреляции. После PCA коэффициенты относятся уже к компонентам, поэтому их нельзя напрямую читать как веса `MMAX` или `CACH`.

```python
train_metrics = calculate_metrics(y_train, y_pred_train)
test_metrics = calculate_metrics(y_test, y_pred)
```

Итоговые метрики считаются на **42 тестовых наблюдениях**. Метрики на train нужны для сравнения поведения на знакомых и новых данных. При прогнозе scaler и PCA не переобучаются.

## 30. Где рассчитываются RMSE, R² и MAPE?

```python
def calculate_metrics(y_true, y_pred):
    return {
        'RMSE': np.sqrt(mean_squared_error(y_true, y_pred)),
        'R²': r2_score(y_true, y_pred),
        'MAPE (%)': mean_absolute_percentage_error(y_true, y_pred) * 100
    }
```

Для теста передаются `y_test` — истинные значения, и `y_pred` — прогнозы для тех же строк в том же порядке. RMSE и MAPE должны быть меньше, R² — больше. R² может быть отрицательным, если ошибка модели превышает ошибку постоянного прогноза средним значением целевой переменной оцениваемой выборки.

## 31. Как из MSE получается RMSE?

```python
np.sqrt(mean_squared_error(y_true, y_pred))
```

Сначала считается среднее квадратов ошибок, затем берется квадратный корень. Например, при ошибках 3 и 4: `MSE = (9 + 16) / 2 = 12.5`, `RMSE = sqrt(12.5) ≈ 3.54`. RMSE не равно средней абсолютной ошибке: в этом примере она была бы 3,5.

## 32. В каких единицах RMSE и MAPE?

RMSE измеряется в тех же единицах, что `PRP`, — единицах относительной производительности. Например, RMSE 75,05 — это не 75,05%.

```python
mean_absolute_percentage_error(y_true, y_pred) * 100
```

Функция MAPE возвращает долю; умножение на 100 переводит ее в проценты. Значение 0,8027 становится **80,27%**. R² безразмерен: 0,889 не означает «88,9% прогнозов правильные».

## 33. Есть ли нули в цели и как это связано с MAPE?

```python
print(y.min())
print((y == 0).sum())
```

Минимум **6**, нулей **0**. Значений, близких к машинному нулю, нет, но малые значения относительно общего диапазона присутствуют. MAPE делит ошибку каждого наблюдения на его истинное значение. Поэтому ошибка 10 при `PRP=10` дает 100%, а при `PRP=1000` — 1%.

Из-за этого высокий R² и большая MAPE могут наблюдаться одновременно. Если бы нули были, обычная процентная интерпретация MAPE стала бы проблемной; в нашем датасете менять формулу не требуется.

## 34. Что показывает сравнение train и test? Есть ли переобучение?

Сравнение выводится в `df_results_before` и `df_results_pca`:

| Модель | RMSE train | RMSE test | R² train | R² test |
| :--- | ---: | ---: | ---: | ---: |
| Linear Regression | 55,836 | 75,054 | 0,838 | 0,889 |
| Ridge | 62,466 | 97,668 | 0,797 | 0,813 |
| Lasso | 58,241 | 86,673 | 0,824 | 0,852 |
| Linear Regression + PCA | 55,943 | 73,152 | 0,837 | 0,895 |
| Ridge + PCA | 62,506 | 97,145 | 0,797 | 0,815 |
| Lasso + PCA | 61,222 | 90,572 | 0,805 | 0,839 |

На test RMSE больше, чем на train, то есть есть разрыв качества. Но это еще не доказывает сильное переобучение: выборка маленькая, а редкие мощные системы сильно влияют на RMSE. R² на test выше, поскольку он нормирует ошибку на разброс **своей** целевой выборки. Значения R² разных выборок нельзя сравнивать без учета этого различия.

Разброс RMSE по фолдам большой. Корректный вывод: оценка зависит от состава выборки; уверенно утверждать отсутствие или наличие сильного переобучения по одному разбиению нельзя.

## 35. Как определяется лучшая модель при противоречии метрик?

## 36. Где стандартизация перед PCA и на чем она обучается?

В отдельном исследовании компонент:

## 37. Где создается PCA и что получает на вход?

Раздел 4.3:

```python
pca_full = PCA(svd_solver='full')
pca_full.fit(X_train_scaled)

pca = PCA(n_components=0.90, svd_solver='full')
X_train_pca = pca.fit_transform(X_train_scaled)
```

`pca_full` нужен для графика всех шести компонент. `pca` оставляет число компонент по выбранному порогу дисперсии. На вход поступают **стандартизованные шесть признаков train**. `PRP` в PCA не передается: PCA ищет направления изменчивости признаков, а не направления, которые лучше всего предсказывают цель.

## 38. Как выбрано число компонент?

```python
PCA(n_components=0.90, svd_solver='full')
```

Число `0.90` задает долю сохраняемой дисперсии, а не фиксированное количество компонент. На полном train четыре компоненты дают **89,92%**, поэтому их недостаточно. Пять дают **96,86%**, и остаются именно они.

Внутри CV число компонент определяется заново на каждом фолде по тому же правилу. Мы не передаем туда число, заранее вычисленное с учетом всех проверочных фолдов.

## 39. Где explained_variance_ratio_ и накопленная доля?

```python
explained_variance = pca_full.explained_variance_ratio_
cumulative_variance = np.cumsum(explained_variance)
```

`explained_variance_ratio_` показывает долю дисперсии каждой компоненты. `cumsum` последовательно суммирует эти доли.

| Компонента | Доля | Накопленная доля |
| :--- | ---: | ---: |
| PC1 | 0,5500 | 0,5500 |
| PC2 | 0,1447 | 0,6948 |
| PC3 | 0,1244 | 0,8192 |

Небольшие несовпадения суммы показанных чисел связаны с округлением. Это **дисперсия признаков**, а не объясненная дисперсия `PRP` и не R² модели.

## 43. Как проверено устранение мультиколлинеарности?

```python
pca_df = pd.DataFrame(X_train_pca, columns=pc_names)
```

## 44. Где повторно обучаются модели после PCA?

Раздел 4.4 содержит второй цикл по `models`:

```python
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('pca', PCA(n_components=0.90, svd_solver='full')),
```

В цикле `search` создается заново для этого конвейера. Ridge и Lasso повторно проходят подбор `alpha`; линейная регрессия также заново обучается. Модели до PCA сохранены в `fitted_before`, после — в `fitted_pca`. `GridSearchCV` клонирует переданные модели при обучении вариантов, поэтому ранее сохраненные обученные конвейеры не затираются.

## 45. Одинаковы ли тестовые наблюдения и правила оценки?

Да. `train_test_split` вызван **один раз**. Во всех шести вариантах используются одни и те же `X_test` и `y_test`, содержащие 42 наблюдения. Меняется только способ преобразования признаков внутри конвейера.

Сохраняются одинаковые пять фолдов `cv`, сетка `alpha`, основной критерий CV RMSE и функция `calculate_metrics`. Поэтому сравнение до и после PCA не связано с заменой тестовых компьютеров или формулы метрик.

## Что стоит помнить на защите

- На исходных данных **нет VIF выше 5**. Не нужно утверждать наличие сильной мультиколлинеарности ради применения PCA.
- **89,92% меньше 90%**. Для принятого порога нужны пять компонент.
- Преобразования учатся на train; при CV — заново внутри каждого фолда.
- Высокий R² не означает маленькую MAPE и не измеряет процент правильных прогнозов.
- Положительный остаток `y_test - y_pred` означает недооценку, отрицательный — переоценку. Неодинаковый разброс остатков дает основания предполагать гетероскедастичность, но график не устанавливает ее причину.
- Лучшая по CV модель может не оказаться лучшей на одном тестовом разбиении. Нельзя подбирать `alpha` по test.
